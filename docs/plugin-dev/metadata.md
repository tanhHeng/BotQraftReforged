# 元数据

> **场景**：我写的插件想分享给朋友用，它还依赖另一个插件和 `requests` 库。插件的身份信息和依赖该写在哪里？

读完这一页，你能为插件选出 ID，写好版本和入口，并声明依赖与资源。准备把单文件插件改成目录插件，或者要分发给别人时，再来读这一页就好。

元数据就是插件的身份证。框架会用它认出你的插件、确认它依赖哪些东西，也会根据这些信息准备可分发的压缩包。

写元数据时，先选 ID，再写其他字段。ID 是插件在框架里的唯一名字：它决定数据目录 `config/<id>` 的位置，其他插件声明依赖时也要用它。所以最好一开始就选一个稳定、好认的名字，后面整理目录会轻松很多。

## 选择声明位置

三种插件形态的元数据位置不同：

| 插件格式                  | 声明位置                                   |
| ------------------------- | ------------------------------------------ |
| 单文件 `.py`              | Python 模块顶层的 `PLUGIN_METADATA` 字典。 |
| 目录插件                  | 插件根目录的 `botqraft.plugin.json`。      |
| `.mcdr` / `.pyz` 压缩插件 | 归档根目录的 `botqraft.plugin.json`。      |

JSON 元数据的格式和 MCDR Metadata 相同，只是文件名用的是 BotQraft 自己的约定。把单文件插件整理成目录插件时，把元数据全部搬进 JSON，再删掉入口 Python 文件里的 `PLUGIN_METADATA`。

## 声明单文件元数据

在插件文件中加入下面的字典：

```python
PLUGIN_METADATA = {
    'id': 'echo_plugin',
    'version': '1.0.0',
    'name': 'Echo',
    'description': 'Reply with the supplied text',
    'author': ['Your Name'],
    'dependencies': {'botqraft': '>=0.1.0'},
}
```

单文件插件的入口就是这个 Python 文件本身。目录插件和压缩插件则要在下面的 JSON 里指定入口。

## 声明目录与压缩插件元数据

在插件根目录创建 `botqraft.plugin.json`：

```json
{
  "id": "echo_plugin",
  "version": "1.0.0",
  "name": "Echo",
  "description": {
    "en_us": "Reply with the supplied text",
    "zh_cn": "复述提供的文本"
  },
  "author": ["Your Name"],
  "link": "https://botqraft.tanh.moe/plugin-dev/",
  "entrypoint": "echo_plugin",
  "dependencies": {
    "botqraft": ">=0.1.0"
  },
  "resources": ["assets", "lang"],
  "archive_name": "{id}-v{version}"
}
```

记得把 `link` 换成你插件实际的项目地址。作者、链接和资源这几个字段按需保留就好。上例的入口代码放在 `echo_plugin/__init__.py`，完整的目录结构见[插件格式](plugin-format.md)。

## 完整字段

下面是元数据解析和打包会用到的全部字段。第二列写的是字段类型，以及省略这个字段时会发生什么：

| 字段           | 类型与省略后的行为                                                                                                         | 用途                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `id`           | 字符串，必须符合 ID 规则。缺失或不合法时，单文件插件按文件名生成回退 ID 并警告；目录与压缩插件加载失败，打包命令也会报错。 | 插件唯一标识。插件依赖、运维命令和 `config/<id>` 数据目录都用它。                        |
| `version`      | 版本字符串；缺失或无法解析时记录警告，并回退为原生默认值 `0.0.0`。                                                         | 框架按这个版本检查插件依赖约束。发布时填写明确版本，如 `1.0.0`。                         |
| `name`         | 字符串；省略时等于 `id`。                                                                                                  | 插件展示名称，也参与省略归档模板时的默认文件名。                                         |
| `description`  | 字符串，或语言代码到字符串的字典；省略时没有描述。                                                                         | 展示描述。普通硬编码文本使用英文，多语言描述使用语言字典。运行时用户反馈通过翻译键提供。 |
| `author`       | 作者字符串或字符串列表；省略时没有作者，单个字符串会转成列表。                                                             | 声明插件作者，推荐统一使用列表。                                                         |
| `link`         | 字符串；省略时没有链接。                                                                                                   | 插件主页、仓库或发布页地址。                                                             |
| `entrypoint`   | Python 模块名字符串；省略时等于 `id`。                                                                                     | 目录及压缩插件的入口模块，使用点分模块路径。                                             |
| `dependencies` | 插件 ID 到版本约束字符串的映射；省略时为空 `{}`。                                                                          | 声明框架及其他插件的依赖。                                                               |
| `resources`    | 相对插件根目录的资源路径列表；省略时为空 `[]`。                                                                            | 打包时加入归档的资源目录或文件。                                                         |
| `archive_name` | 文件名模板字符串；省略时由打包命令生成名称。                                                                               | 设置默认归档文件名，可使用 `{id}`、`{version}`，由 `-n` 覆盖。                           |

### ID 与入口

ID 要符合 `[a-z][a-z0-9_]{0,63}`：以小写英文字母开头，后面跟小写英文字母、数字或下划线，总长 1–64 个字符。挑一个和其他插件区分得开的 ID，并且长期保持不变。

目录插件和压缩插件的 `entrypoint` 只能是 `id` 本身，或者 `id` 下的子模块；写成别的模块名，元数据会解析失败。例如 ID 为 `echo_plugin` 时，可以写 `echo_plugin` 或 `echo_plugin.main`，对应的代码分别放在 `echo_plugin/__init__.py` 或 `echo_plugin/main.py`。

源码包目录必须和插件 ID 同名。如果插件根目录下还有其他带 `__init__.py` 的 Python 包，加载会失败。打包命令也只会自动收集根目录下以 ID 命名的那个源码目录。

### 依赖

依赖框架本身时，插件 ID 写 `botqraft`。实例里还有一个内置的 `python` 插件，它的版本就是当前的 Python 版本，可以用来声明对 Python 版本的要求。BotQraft 实例里没有 `mcdreforged` 插件，从 MCDR 迁移过来的元数据要把它换成 `botqraft`。

```json
{
  "dependencies": {
    "botqraft": ">=0.1.0",
    "another_plugin": ">=1.0.0"
  }
}
```

版本约束的写法和 MCDR 一样，例如 `>=1.0.0`，意思是运行实例里要有不低于这个版本的插件。框架会在调用插件的 `on_load` 之前检查依赖。缺少依赖或版本不满足时，插件不会被加载，日志里会写明原因。如果某个依赖项的约束写法不合法，框架会忽略它，并记录一条警告。

版本字符串请写具体的版本，通配之类的要求留给依赖约束。

Python 第三方库写在目录插件或压缩插件根目录的 `requirements.txt` 里，和插件依赖分开声明。框架不会替你安装这些库，请先在运行实例使用的 Python 环境里装好它们。加载插件时，框架会检查它们是否已安装、版本是否满足，不满足时插件加载失败。单文件插件没有 `requirements.txt`，请在说明里写明需要哪些库。安装步骤见[插件格式](plugin-format.md#安装依赖)。

### 资源与归档名称

把翻译目录 `lang` 和其他只读资源列进 `resources`，它们就会随插件归档一起分发。打包时，每一项都会以自己的名字放到归档根目录。所以这里只列插件根目录下的直接子项，例如 `assets`，不要写 `assets/images` 这样的嵌套路径。运行时，用 `server.open_bundled_file('assets/help.txt')` 读取这些资源。需要保存的可写数据，则放进 `server.get_data_folder()` 返回的目录。

`archive_name` 里的 `{id}` 和 `{version}` 会被替换成插件 ID 和版本。省略模板时，打包命令用去掉空格的展示名称和版本生成 `<name>-v<version>`；展示名称为空时改用 ID。如果名称缺少受支持的后缀，命令会自动加上 `.mcdr`。想用 `.pyz`，就在模板或 `-n` 里把后缀写明。
